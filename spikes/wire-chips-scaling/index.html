Wire chips at dome scale

The patch bay draws one bordered cell per run, positioned as a percentage of its track. At peach scale (3 runs) that reads beautifully; on the small dome the fixture row is 5950 lamps · 50 runs — a 7px-per-cell smear — and the big dome quintuples it. This playground explores how the strip should degrade with density while keeping the things that make it good: the track-shows-through-gaps idiom, per-run hover with twin lighting on the other face, selection, and the small cases utterly unchanged. Hover any run anywhere — every concept lights the same run everywhere (the twin-hover contract). Click selects.

1 · Today, faithfully

The production rendering: fixture rows ordered by the fixture's own channel space, the output card one row per port. Judge what actually breaks — and notice the output card's height as much as the fixture card's smear.

2 · Concept A — source ribbon, adaptive detail

Same ordering as today (the fixture's own space), but the row is one continuous pixel ribbon — which is the honest picture, since the runs tile it edge to edge. Run cuts become hairline ticks; a thin destination band underneath colours each span by the box (and alternates shade per port) so wire structure is visible with zero labels. When a cell would be wide enough to label (peach), it renders exactly today's boxed cells — one primitive, density decides. Hover resolves the run under the cursor into the readout line.

3 · Concept B — wire-grouped strip, dive to port

Reorder the strip by where the lamps landed: one lane per box, port segments left to right. This is the grain that actually aggregates (source order scatters across ports, wire order nests cleanly: box → port → run). Segments label themselves when they fit and go quiet when they don't; click a port to dive — the studio's existing single-click dive gesture — and its runs open full-width below, legible at any scale.

4 · Concept C — elide at rest, lanes on demand

Keep today's chips but refuse to draw 50 of them at 7px: at rest the row is a structural summary (counts + a per-box mini swatch), and expanding wraps the full run list into lanes — every chip at a legible width, grouped by box, however tall that gets. Peach never elides, so the small case is today's row untouched.

5 · The output card at 13 ports

The output face stacks a ports section and a patch section — 26 rows for one small-dome box, ×10 cards at big-dome scale. Left: today. Middle: fused rows — the patch strip rides inside each port row (the caption line it already has), halving the card. Right: box ribbon — the patch section becomes one wire-ordered ribbon with port ticks (concept A's primitive on the output side), constant height at any port count.

Lean. A + B are one system, not rivals: keep the fixture row source-ordered and density-adaptive (concept A — it is today's row at small scale, and its destination band answers "which box/port" without labels), and give the output card the fused port rows (5-middle) with the box ribbon reserved for the patch summary. Concept B's dive gesture then hangs off either row as the detail path. Concept C's lanes feel like a spreadsheet answer — honest but joyless, and 44 lanes at big-dome scale convinces nobody.
