Props stack — the selected path as editable levels

G1 follow-on to the one-project-canvas: the Props dock currently shows one level at a time (the selected node's fields, a breadcrumb standing in for ancestors). Yona's stack idea: one card per level of the selected path — module > fixture > group > object — each level editable in place. The real chain is often five deep (the root show sits above the module), so every concept here must survive a chain longer than the nominal four. Concepts C and D split a real semantic question: is the stack the selection (clicking an ancestor ascends it, canvas follows) or a local accordion (peek and edit an ancestor without moving the canvas selection)?

All four columns render the same selected path at dock width (322px). Change the selection or dataset above — every column follows. Fields are live where the design question is live: edit the repeat's instances count and watch the group's ×N label update in every concept.

Lean: C (selection stack). It keeps the whole chain visible and clickable — the context the breadcrumb hid — without the wall-of-fields cost of B, and it keeps ONE selection model (the stack mirrors it) instead of D's second, local disclosure state. B is the strongest counter-argument when the chain is short; D wins only if editing an ancestor without ascending selection is a real workflow, which the canvas already covers (click the parent there).
