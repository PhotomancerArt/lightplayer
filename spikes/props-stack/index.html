Props stack — the selected path as editable levels

G1 follow-on to the one-project-canvas: the Props dock currently shows one level at a time (the selected node's fields, a breadcrumb standing in for ancestors). Yona's stack idea: one card per level of the selected path, each editable in place. Scope ruling (round 2): the stack shows only the levels the Mapping view actually EDITS — the fixture's placement (editor.json, an arrange concern, never node config) plus the authored document levels (group > object). Module/show levels are context, homed in the Fixtures tree; a node level rendered here would have to be the REAL node card re-housed whole (the workbench's re-house-don't-redesign rule), which is a someday-unification, not this design. The module chain survives as a muted one-line context strip. RULED (round 3): B′ — full stack, deepest first. The selection is always the top card (inspection-panel convention: DevTools styles, debugger call stacks), ancestors unwind beneath, module context at the bottom; editing the repeat while its inner item stays selected is the workflow this exists for. The losing concepts are kept below as a rejected-because strip.
