Wiring UI — visualizing the bus

The question: how do we show the bus to users? Three things must surface — the channels, the bindings on them (writers and readers, with their flavors: default-origin, inherited, engaged panel writers, module publishes, E3 contention), and what's on the channel (the live value or product — a visual.out should show its picture, not a debug string). It should be one hop from wiring to value. This spike also trials selection as a new UI concept: click any channel or binding site — the readout in the strip below tracks it, and the target flashes everywhere it appears (stand-in for "selection jumps to the actual thing"). Hovering a node chip highlights that node everywhere. A proper node-graph view is real but later; these are the drawer-scale answers. Section 6 carries the CONTROLS-vs-PANEL nomenclature question.

2. Horizontal flow — [writers] → [value] → [readers]

The sketch, literally: writers enter left, the channel box holds the name and what's on the channel, readers exit right. Wire weight carries resolution — the winning writer's wire is solid violet, shadowed writers dim to dashed, E3 contention turns both wires orange with the pick affordance on the box. Reads as dataflow without being a free-form graph: still a per-scope list, one channel per row.

3. Vertical flow — the same diagram, rotated

Writers drop in from above, the value box sits mid-lane, readers tap off below; channels stand side by side like console strips and the strip scrolls sideways as a scope grows. Products get room to be pictures. Strongest at "what does this scope carry"; tightest on horizontal space for long site lists.

4. Value cards — the value is the hero, the wiring is the caption

One card per channel: the live value/product as the hero, writers and readers as two visible lists underneath — the current design's monitoring strength, but with the popup's contents promoted onto the card. Cards pack into a grid, so a big scope stays shallow instead of tall. The least diagrammatic option: no drawn flow, just legible lists.

5. Matrix — nodes × channels (wildcard)

The inverse pivot: rows are nodes, columns are channels, cells say Writes / Reads; values live in the column headers. Answers "what is this node's bus footprint?" — the question every flow view makes you hunt for. Scales best, reads coldest; if it earns a place it's as a second view behind a toggle, not the default.

6. Nomenclature — CONTROLS vs PANEL

Today a leaf card labels its knob strip CONTROLS and a module card labels the identical-looking strip PANEL. The ratified docs already resolve the concepts: every node has a panel (R8), and a control is one channel's presentation on a panel (panel.md P1). The question is only what the section rail says.
