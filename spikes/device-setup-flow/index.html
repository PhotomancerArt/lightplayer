2 Where naming goes

Today the name field sits in the setup form next to the board picker. Naming is hardware-only (the single sim stays "Simulator"), and the stamp lands post-flash at hello anyway — so the field can move. My lean: B · name it while it flashes.

A · With the board steptoday's grouping

Board thumbs + name field together, like the shipped form. Familiar; but it's a second decision before anything happens, and the default name ("2026-08-04 - esp32c6") gets accepted unread. Name your device

B · During flashlean — the dead minute

Flash takes ~a minute of enforced waiting. The name field rides beside the progress view: "while it writes, what should this board be called?" Zero added steps; the name is stamped at hello right after. (Live in §3's flash step.) While it writes — name this board

C · At the endafter first light

"It's glowing — call it something." Emotionally right (name the thing you can see), but it gates the editor handoff on one more decision, exactly where momentum matters most. It's glowing — name it

3 The flow, live — inject failures

The A-takeover wizard with every state reachable. Path and Inject in the controls strip; injections land where they would in reality (port check at open, probe at board, flash at 42%). Close (✕) during a flash to see the abandon guard. Boards filter to the detected chip on the hardware path, exactly like the shipped picker (+ Generic escape hatch).

‹ devices Connect a device Hardware

Failure treatments shown (lean per state): port held — blocking error at open with "try again" + name-the-culprit hint (a serial monitor or another Studio tab), because retry actually fixes it once the culprit closes. probe finds nothing — never blocks: full catalog + Generic, with a quiet warn note; flash refusal stays the device's job later. already set up — an adopt branch before the board step: adopt as-is (no flash) is the primary action, full re-setup is the escape. flash fails — fail in place on the checklist (✗ Write firmware), log tail kept, Retry re-runs from erase; a second failure adds the replug guidance (never trust an incomplete flash). close mid-flash — confirm sheet; abandoning marks the card "incomplete flash — needs re-flash", not silently fine. zero projects — Load pane empty-states and New is preselected; the flow never dead-ends.
