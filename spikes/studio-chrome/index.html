1 · The workbench

Full-height under the (slimmed) site header. Edge strips carry the four panel toggles — left strip: Nodes · Fixtures; right strip: Device · Outputs. A strip button opens its panel in the side's dock; in radio mode (default — the ruling's expectation) it replaces the side's open panel, and re-clicking collapses the side; stack mode (strip control above) lets a side hold both. View tabs switch the center only. Panel visibility is remembered per view (R3-2 ruling: try it and see how it feels), seeded by defaults — Nodes opens the Nodes tree + Device; Mapping opens Fixtures + Outputs — and any panel can be summoned in any view (the "always there" rule: check a port's occupancy without leaving Nodes). Patching is a mode inside Mapping. Future views ride the same tab row (greyed).

Everything here is live: edge-strip toggles, view tabs, mode segment, tree/cell selection, density. Selection is one system — click a fixture row, canvas frame, or port cell and every open panel follows.

2 · The four panels

One panel, one role — no double duty. Nodes (né Project — the whole workbench is the project) stays the assembly tree: all nodes, add, structure. Fixtures and Outputs are project-scope slices: the multi-node analogue of the custom node faces, derived from the same graph + node selection + on-selection body loading the app already has. Device is the card that exists today, docked.

Nodes

Assembly + structure. All nodes of the graph, tree-shaped; add node; advanced tinkering. No fixture chips — that's the Fixtures panel's job.

Fixtures

The light-side slice. fixture → object → instance with channel chips, mapped/unmapped state, object colours. Selection here focuses the Map canvas.

Outputs

The hardware-side slice. box → port → wire-window cells, occupancy, gaps, contested ranges. Radiance density (10×32) must stay legible — toggle it above.

Device

Today's device card, docked. Run state, lamps, frame, power; the sim / hardware surface. Unchanged by this rework.

3 · Future views (same tab row, zero new chrome)

The test of the model: adding a view = a center tab + panel defaults. Live / Perform puts the root panel front and center over a read-only map strip (kiosk mode; maybe what ships on device). Show gets playlists / timelines. Neither is designed here — the frames only prove the chrome doesn't change shape when they arrive.

4 · Mobile — the edge strips fold into the summon strip

Same model, folded: the main view is full-screen; the sticky strip carries the view switch and the same four panel toggles the desktop edge strips carry. Summoning a panel temporarily replaces the main view; back returns. The first phone is live. The tablet frame is the md middle: one dock open, the other side stays a strip.
