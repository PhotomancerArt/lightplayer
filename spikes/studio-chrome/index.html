Studio chrome — the session·project control, single-session world (round 8)

Rulings since round 7 (Yona): concept B (segmented lockup); Save/Revert in the group ("at least to try it out"); click grammar confirmed. And the bigger ones: one session per tab — one device OR one sim, "want another? open another tab" (the pool keeps its N-session shape; capacity is policy) — and navigation is studio OR site: leaving the studio ends the session (edits are safe — the dirty overlay is persisted; the session is disposable, the document is durable). Consequences drawn here: the session strip and the ⋯-menu Sessions group retire; the detail popup is reworked into the control's panel (device zone + project zone, no switcher); Docs/Explore from studio open a new tab. 1 · The control closed — three widths, one grammar

The only session UI left in the chrome. lg carries the full lockup; md drops the device name (glyph + dot keep the kind and health); sm keeps name + count + Save (revert retreats into the panel). In studio mode Explore and Docs wear the new-tab mark (browsing beside a running session = two tabs); Devices and Projects are plain exits — leaving ends the session. Flip project and session above; click any group to open its panel.

2 · The panel — device zone + project zone, no switcher

One panel replaces ProjectDetailSections: the device zone (kind, name, run state, live stats — the half the old popup never had) over the project zone (name, save state, the unsaved list with per-entry revert, Save/Revert), then share and project facts. Identical at every width — one content, one mount (no container-query double-mount). There is deliberately no session switcher: this tab IS the session.

3 · Live — drag the dome, watch the control

The full workbench under the new chrome. Drag the dome: the pencil + count light the project segment and Save · ↺ materialize as trailing segments. The Tree panel's Save/Revert row is gone (R7-2: one home — the control; the panel detail is the second read of the same state, not a second home).

4 · Leaving — the site side, the toast, the guard

Interactive: in the bar below, click Projects to leave the studio — the session ends, the site header takes over (no group anywhere), and the toast says what happened and what survived. With deploy in flight (toggle above), the same click is refused — the one nav guard; dirty alone never prompts, because the draft is durable.

This is the payoff of the single-session ruling: the chrome carries exactly one session object, the panel answers "what is this tab?" in one glance, and the leave story is honest because the document outlives the session. The control is rich where richness pays (states, panel, save moment) and the whole switching layer — strip, ⋯ sessions, washed off-editor chip — simply stops existing.
