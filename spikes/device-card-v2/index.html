Device card v2 — the four zones, dressed

Thesis. The card's structure is settled (header / state / terminal / actions, always present, fixed-height panels absorbing churn). What is not settled is how the zones look and three interaction questions the shipped card gets wrong: an armed chip that changes width and reflows the row (§2), a terminal you cannot copy from or read at a glance (§3), and a picker that is an inline list growing with your library (§4). §1 assembles the candidates into whole cards; §5 carries the pending-link and add cards in the same idiom. The preview slot is back in every concept, wearing the honest-preview grammar (live / stale / last-seen / no picture) even though its feed is a separate milestone.

State Preview

1 The whole card — four concepts

Same DTO, same zones, four dressings. Current is the shipped renderer reproduced faithfully (no preview slot, inline pickers, reflowing chips). A · Stage puts the preview on top of the state zone as the card's picture and reduces every face to “one line + one verb”. B · Split keeps the preview small beside the state text and moves every always-action under a ⋯ menu so the footer never grows. C · Instrument is the dense reading for a bench with eight boards: identity as tags, a 4-line terminal that opens as a sheet, actions as fixed slots. Cycle the state above; all four follow.

2 The actions row — arming without reflow

The shipped 2K+ chip opens a “Confirm ” grid column when armed; in a wrapping footer that width change pushes neighbours and wraps the row. Four answers, each measured live: arm a chip and read the meter under the stage. Reserve renders both labels in one cell and hides one (the spike's 2D, revived). Slots gives every verb a fixed cell. Menu moves the destructive family off the row. Swap keeps a fixed cell and changes the verb text itself (“Factory reset” → “Confirm reset”) rather than prefixing.

3 The terminal — readable, colour-read, copyable

Three defects in the shipped panel: rows are fed newest-first into a column-reverse box so drag-selection follows reversed DOM order (try selecting in Current and pasting), the text is subtle-on-subtle at 10.9px, and every line is an untyped string. T1 · Typed keeps natural order with a pinned bottom, types lines (ROM / board / wire / Studio / outcome) and decodes wire frames into one readable line. T2 · Brackets folds activity narration into collapsible groups. T3 · Ticker shrinks the zone to one line and opens a sheet in place. All keep a fixed footprint.

4 The picker — a popover, not a list

Today both faces (which board? / put something on it) are inline option-card grids; the second grows with the library (toggle “Library: 40 projects” above and watch Current). The candidates make the face one line — a trigger showing the pick — and open the choice as a popover that reuses the real gallery cards with their thumbs. P1 · Gallery is a tabbed card grid. P2 · Palette is a searchable list with a preview pane. The board pick uses the same trigger, filtered to the detected chip, with the filter stated and escapable.

5 The family — pending link and add card

The roster's other two cards in the leading idiom (concept A). A pending link is not yet a device: it carries no preview and no always-actions, and the same flash face appears on it once the verdict settles. The add card is the empty state, unchanged from #482.
