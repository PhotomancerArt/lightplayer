Palettes — panel control · picker · editor · inheritance

Companion to the palette exploration spike (planning: 2026-08-03-1803-palette-exploration-spike). Thesis: a palette is a value on a bus channel — the panel control is a latch-mode writer like any knob (panel.md P2), sharing is scope inheritance (modules.md R5/E4), and anything that animates a palette is a node. This playground explores the three surfaces that need visual judgment: the panel swatch control (§1), the picker (§2), the gradient editor + interpolation space (§3), and the drop-in inheritance story WLED can't do (§4). Engaged/captured treatment is candidate gold — deliberately not the bound-violet family (P6, P-Q2).

1 · The panel swatch control

Where the current palette lives on a panel, seated between a real knob and fader for scale. Cycle the state strip above: Read·default (no writer anywhere, authored default), Read·inherited (host scope writes it — violet live readout), Read·automated (a future generator node animates it — grabbable, P5), Engaged (panel writer holds it — gold + ↺). Lean: A — the strip is the value; a palette control that doesn't show the gradient at readable width isn't a palette control. C's stepper is a play-mode overlay on A, not a rival.

2 · The picker

Opens from the §1 control. All three share the same catalog model: Project (customs, saved in the project), Stock (FastLED-lineage), Classic (cpt-city-lineage), plus a WLED-JSON import affordance. Search filters live in A and C. Click any row/tile — the §1 control follows (that's a real PanelWrite in production). Lean: A — WLED users know exactly what this is; strips at list width stay legible at 60+ entries. C's live LED preview is the demo-magic add-on if the budget allows; B's grid goes illegible with subtle palettes.

3 · The gradient editor + interpolation space

Authoring-grade (face/drawer), not panel-grade. A: direct manipulation — drag stops, double-click the bar to add, color-well edits the selected stop. B: stop list — precise, boring, phone-friendly. The comparison grid renders the SAME stops through every space × method pair (real Oklab math, live): this is decision D8 made visible. Lean: A over B as the primary, with B's rows available as a disclosure ("exact values"). D8 leans: imports = srgb/linear for WLED fidelity; new palettes = oklab/smooth.

4 · Drop-in inheritance — the thing WLED can't do

A host module and two embedded plasma effects, all consuming bus:palette. Untouched children inherit the host palette (R5). Click a child's swatch to engage its own panel writer — gold ring, that subtree detaches (R11), the sibling still follows the host. ↺ clears back to inheritance. Change the host palette (click its strip) and watch who follows. This interaction demo is one concept, not a matrix — it's the acceptance scenario for M4, and the flow lines under each group are the candidate "whose value is this" affordance.
