Spike for T1 (2026-08-07-1017-module-authoring-unit): the published unit is the whole workbench project with a plural publishes: designation; import vendors the designated module folder, fork opens the project. Explored here: how a family workbench reads at a glance (§1), the designation gesture + publish lint (§2), the import-vs-fork verb pair on a content card (§3), and workbench template entries at project creation (§4). Seed content = the yona-noise family: rig (clock, strip 300×1, matrix 32×16, drive control), a non-published common helper module (the lint specimen), and three published effects. 3 Import vs fork — the verb pair on a content card

Where pack content is consumed (T4 owns the page; T1 owns the verbs). Add to project = vendor the designated folder, copy-to-own. Open workbench = fork the whole project, rig included. Family cards carry both a single effect and its siblings.
