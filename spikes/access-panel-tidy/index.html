Access panel — two passwords

Yona, round 4 (2026-10-02): “Try again … something closer to Google Docs … it occurs to me you might want view with no password, only edit password. So maybe it’s just two options — the play and edit passwords. If they’re off, then you can do that thing without a password. The shared keys bypass it. … and that should be on the top of the box.” Earlier, still standing: call edit Author; a password is prefilled with a random one you type over; saves when you click away; old browser keys make room automatically; “this isn’t enterprise banking software.”

The model: two choices. Play: Anyone → anyone nearby can play; Password → it takes the password. Author the same, for changing the show. Your browsers and your account always get in — those keys are added when you plug in by USB and sit in one quiet line below. One rule falls out: anyone who can author can play, so while Author is Anyone a play password means nothing — Play rests on Anyone (“follows Author”), and setting Author to Anyone sets Play with it.

Needs a board change: today the store’s open is a yes/no that grants play only (lpc-access/src/device_access_file.rs, store version: 2). “Author password off” means anyone nearby can author, so open becomes a tier — none / play / author — in a version 3 store with a v2 reader (persisted format: migration in the same change). Everything else here is Studio.
