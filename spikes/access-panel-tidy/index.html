Access panel, tidied

Yona, 2026-10-02: “Per-origin makes sense … it’s the UX that sucks. The list gets super long, custom passwords are hard to enter, and I had the ‘allow everyone’ thing not work. Security matters but right now it’s getting in the way. Collapse/group the things that have access, and make it much easier to enter a custom password. We can offer a random one, but it should be as easy as just replacing the text to change it.”

Round 1: list = 1B, grouped by name. Passwords: “one box for play password, one for edit. Button to regenerate. All the add, and choose and crap is too complex. Two rows, with a checkbox/toggle, default to a random pw, let the user override.”
Round 2: “Let’s call it ‘Author’ password — Edit sounds like you’re editing the password. It looks good, it’s a lot of vertical space, see if you can tighten it. I really don’t like the ‘keep newest’ thing — no one is going to have any idea what that means. It should just be automatic. We can drop old browsers if we run out of space.”

Round 3. No cleanup buttons. When the board is full and something new needs a place — a browser plugging in, a password turned on — the browser that was added longest ago makes room. Never this browser, never the account, never a password. The header says it when full, and the toast says what made room. Copies of one name still fold into one row (that’s just how the list reads). Passwords are one line each: switch, name, the password, ↻.

Round 3 (converged): a friend’s browser being the one dropped — “I know and I just don’t care.” Turning a password off with no confirm — fine. A typed password saves when you click away (Save and Enter still work). No share QR. “I just really want this to be simple … this isn’t enterprise banking software.”

Why the choker filled: 16 × “Brave on Mac” (XIAO C6 10:bd:a3:b0:8e:30, Sep 26 → Oct 2): each worktree’s dev server is its own origin, so its own browser key, and 16 is the board’s cap. Under this rule the next plug-in just replaces the Sep 26 copy.
