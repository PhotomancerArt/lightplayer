Mapping & patching surface — design spike

Vision: 2026-08-09-0048-mapping-patching-surface. One surface, modes — arrange (ground state) / map / patch. Patch = sparse anchors over auto-flow, per fixture. Visuals display in their native sampling dimension: 2D = plane below the lamps, 1D = a rope threading the LEDs. This playground tests the feel of those calls on the peach (slice 1) and a mini-dome (slice 2). Everything animates live; nothing here is production code.

2 · the peach — patch mode, three treatments

One physical strip (wire runs from Yona's reference art): bottom → up one side (body, ch 0–21) → across the leaves (ch 22–33) → back down the other (body, ch 34–55, reversed). Body and leaf are separate fixtures on one output. Use the §2 patch state buttons above: auto-flow shows why patching must exist (fixture-order flow puts the leaf pattern at the bottom of the down-leg), no reverse breaks the gradient symmetry, overlap shows guided diagnostics — contested lamps red, orphaned lamps dark. C — universe rail (lp2014)

out Apatch · table

The proven grammar (lp2014 shipped this): rows per range, keyboard-friendly (r reverse, ;/' nudge). Dense, exact — but you patch a spreadsheet, not a peach.

Lean: A as the primary surface with C's row list docked beside it at real scale (the mapping editor already has a rail) — B's bar folds into A as the fragment ticks. The overlap affordance must exist in whichever wins: red on the lamps, click → counterpart, plain-language fix hint.

3 · rope vs plane — same shape, both declarations

D26v, the crux. The same mapping shape, flipped between declared-1D and declared-2D ("show visual" toggle in the strip above): declared 1D shows the visual as a rope snaking the wire; declared 2D shows it as a plane below the sampled lamps. Presentation never changes — only the sampling dimension does. Nobody needs the lecture after seeing this once.
