This round, one section per part of the card, top to bottom in Yona’s order: project and status · where and connection · firmware · hardware. Two rules for every option: a card never changes height (rows never appear or disappear; a notice only tints its row), and no boxes in boxes (a notice is its row, edge to edge). The card is two components: one special name bar with the primary action, then a standard stack of bars that hold info and actions (below). The primary action connects to a board or opens it, across the three levels of connection. The page uses the leans; the questions are lettered to match the chat. Click a picture or name to open; click a firmware or hardware row for details.

The three levels of connection (vision D23–D26)

WatchingThe picture and status, with no Studio session. Cloud-connected boards are watched through the cloud; a nearby board over its link (USB opens without asking; Bluetooth needs one tap to pick it; Wi‑Fi dials the address it last gave). Watching never blocks anyone.
ConnectedStudio holds a link it can open a session on. For a direct board, connecting is what starts watching it. The row says the link: “USB”, “Bluetooth”, “Wi‑Fi”, or the cloud.
OpenThe Studio session: the editor, with this board as the target. One per board; a watch steps aside for it, and someone else’s open shows as “Sean is editing” or “Open in another tab”.

Two components, driven by data (Yona: “one special bar that’s the main name / CTA, then a standardized stack of bars”)

Like the node cards: the view model (in core, so every button is an offer the agent can see and press) says what is in each part; the components decide how it looks. The same two components can later carry project and pattern cards.

Q6What does the where-and-connection row say?

Where the board belongs, and how Studio reaches it right now. This row also carries connection notices: someone else has it, it’s offline, it’s locked.

Q7How does the name bar carry the primary action?

Watching is automatic where it can be; connecting a nearby board may need a tap (Bluetooth asks for one); opening starts a Studio session. The primary action is whatever gets you in next.

Q8What does the firmware row say?

Porch is current; Fyeah Sign’s board is a release behind. Updating and “no firmware” tint the bar either way.

Q9What does the hardware row say?

The real thing: grounding, not detail. The rest is in its popover.

Q10Where does access live?

From your note: “the access control needs a bar too, probably, or it lives in the connection spot.” Access is what you can do with this board (play, edit, nothing yet) and the key that lets you.

Decided so far
  • Round 1: the stack card, with firmware and hardware on every card (“much better”). Notices tint their layer’s row (Q1 → A); a status in the corner is fine too as long as it’s cut out of the card, not a pill (now Q5).
  • Round 1, Q2 → A by the height rule: an action sits flush at the end of its row; a full-width last row would change the card’s height.
  • Order of rows (Yona): project and status · where and connection · firmware · hardware.
  • Fixed height (Yona): try hard never to change a card’s height.
  • Round 2, Q4 → none of them: never cover the picture; let it be taller. The name bar sits under it, one line: the name and the primary action.
  • Round 2, Q5 → A, with an icon: the status is cut out of the corner and shows an icon (blue dot when fine, an orange or red sign for the worst warning or error on the card) and the frame rate; clicking it opens the status popover, which lists every notice.
  • Round 2: the project gets its own bar, first in the stack (“might be redundant, but I wanna see”).
  • The vocabulary (glossary, colours, actions by consequence) is spikes/board-card round 2; its open questions fold into this spike next round.
