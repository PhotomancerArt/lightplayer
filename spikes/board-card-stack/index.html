Q12What does the primary action look like?

Q11 is settled: the primary action is a section of the name bar. Now its look. One rule from Studio’s style guide decides a lot here: the spectrum is the pointer’s answer, not resting chrome (“multi-color is a moment, not a wall”), and a static spectrum line under a word already means “you are here” on Studio’s tabs. Q13How does work in progress show?

A firmware update, start to finish, then a project being sent and a board connecting. In every option the bar doing the work goes neutral and says what’s happening with Studio’s spinner. Progress never sits on a status colour, by the style guide. Afterwards it’s green for a few seconds, or striped with Retry. The options differ in where the progress itself shows. From your note: “probably replacing the lights.”

Q14The rows become the panel. How does it look?

From your notes: “connecting opens the panel for controlling it, and loading it in Studio is a separate edit action”, and “when you connect a card, all the rows disappear and become the panel.” The panel is the board’s own controls: brightness, speed, palette and whatever the project publishes, which is exactly what the play password gives. Assumptions behind this round

  1. A1. The panel on a card is the board’s own panel (vision: the board serves its panel), its first controls in the board’s order. The rest are behind All controls, which opens the board’s own page (today’s play mode, /device/…/play).
  2. A2. The play password (or a play share) is enough to connect and use the panel; Edit needs the edit password. That’s access as shipped.
  3. A3. The card shows the board’s facts while it’s watched and its panel while it’s connected. Done disconnects: the board goes back to being watched, and its connection is free for someone else.
  4. A4. You can connect while someone else is editing: the panel is built for several phones at once (panel.md P9). Today a C6 has one network slot, so a second client over Wi‑Fi or the cloud is a firmware question this needs answered.
  5. A5. During an update you can’t connect; the panel comes back with the board. Notices that arrive while you’re connected show in the status corner.
  6. A6. The project bar’s icon changes from ▶ to ✳, so a play triangle means one thing.

The components, driven by data

Three bar kinds now, all built in core as offers the agent can see and press: the name bar (one per card), stack bars (the board’s facts), and control bars (its panel). Watched, a card shows its facts; connected, its panel.

BoardCard {
  picture:  Picture { feed: Live | CloudFrames | Still { age } | Work(Progress) }   // Q13-B: the lights carry the progress
  status:   Status { worst: Fine | Working | Warning | Error, reading: Fps(58) | Age("5 h ago"), details }
  name_bar: NameBar { title, place, primary: Offer }     // devices/<board>/connect · unlock · install · done (disconnect)
  face:     Facts { bars: [StackBar] }                   // watched
          | Panel { controls: [ControlBar], all: Offer } // connected (Q14 says how many, and how they look)
}
StackBar   { layer: Project | Connection | Access | Firmware | Hardware, icon, summary, aside,
             tone: Option<Tone>, action: Option<Offer>, work: Option<Work>, details }
Work       { words, progress: Percent(64) | Unknown, ends: Done(words) | Failed { words, retry: Offer } }
ControlBar { channel, label, widget: Fader { v } | Step { options, i } | Momentary, engaged: bool, clear: Option<Offer> }
Decided so far
  • The stack card (round 1, “much better”): a picture, the name bar, then a stack of bars. Notices tint their bar; actions sit flush at a bar’s end; a card never changes height; no boxes in boxes.
  • Order: project · connection · access · firmware · hardware.
  • The picture is never covered (round 2); the name bar sits under it.
  • The status is cut out of the picture’s corner: an icon for the worst notice (a blue dot when fine), then the frame rate or the picture’s age; it opens its own details (round 2, Q5).
  • Details open as Studio’s detail card, merged with the bar that opened it (Q3 → A).
  • The group sits under the name; the connection has its own bar (Q6 → D).
  • One primary action at the end of the name bar, always the way in (Q7 → A), as a section of the name bar (Q11 → B, “I generally like it”); its look is Q12.
  • Firmware says the version and nothing else; older than the newest, it turns blue and offers Update (Q8 → A, revised).
  • Hardware says the board model only; the LED count is the project’s (Q9).
  • Access has its own bar (Q10 → A, taken from the lean; it wasn’t answered, so say if not).
  • No “open in another tab / take over” on the card: Studio finds out when you connect, and offers to take over then.
