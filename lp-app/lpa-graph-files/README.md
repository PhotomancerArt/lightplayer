# lpa-graph-files

Opening and saving real LightPlayer projects for the Graph, Studio's one
project canvas and mapping editor. It reads a project into `lpa-graph`'s
model and writes back what a person changed, in the product's own formats:
project format 12, and each fixture's mapping in map2d format 6.

```bash
cargo test -p lpa-graph-files                                     # opening, saving, the journeys
cargo run --release -p lpa-graph-files --example scale_bench      # the model's per-frame work on the radiance dome
```

## Opening

`Opened::open` reads `project.json`, the root module and every node it
refers to: fixtures with their mappings, outputs with their ports,
modules, shaders (their GLSL kept, to show; the Graph never runs it), and
every other node as a plain card. What the Graph doesn't model (other
nodes, unknown fields) is kept in a `ProductProject`, untouched.

A fixture's mapping is read by `lpc-mapping`'s format-6 reader, the one
the engine runs, so what the Graph shows is what the board does. A
project at another project format, or a mapping in an older map2d format,
is refused by name. The upgrade (`lpa-upgrade`) is what brings an older
project forward.

Files come from a `Source`: a directory on disk (`DirFiles`), files held
in memory (`MemFiles`), or Studio's own, which answers from what it has
fetched from the board and fetches what the open asks for
(`lpa-studio-core`'s `graph_source.rs`).

## Saving

`ProductProject::save` writes only the files the Graph owns (module node
maps, fixture and output nodes, each fixture's mapping) and only when what
they say changed. Saving an unedited project writes nothing, and a file
nothing changed stays byte for byte as it was.

- A fixture's mapping is written by `lpc-mapping`'s own format-6 writer.
  Nothing here shapes a mapping's JSON by hand.
- A node file starts from the JSON it was read from, so fields the Graph
  knows nothing about are kept.
- A shader the Graph opened is never written. One the Graph made is
  written as a shader node with a small stand-in GLSL file.
- A name the product would refuse (`tail rig`) is written as one it
  accepts (`tail_rig`).

In Studio, a save goes through the ordinary asset edit; see
`lpa-studio-core`'s `app/graph/`.

## The baked-in projects

`embedded.rs` bakes some of the repo's own projects into the binary, so the
Graph's stories (a browser with no disk), the tests and the scale bench can
open them: the PLAYFUL choker, the zook dome and the fiber headband
(`catalog/projects/`), the plasma pattern (`catalog/patterns/`), and from
`projects/test/` the radiance dome (generated by `tools/lpt-radiance-gen`,
with placeholder counts), Sean's eaves and `eaves-wired` (the house as it
is really wired), and the circular display. Only what the Graph reads is
baked in: the JSON, and each shader's GLSL.

## Statements and journeys

- `tests/open.rs`: what each real project opens as, and what is refused.
- `tests/save.rs`: the Graph saves exactly what a person made, and nothing
  when they made nothing. It walks every project under `catalog/` and
  `projects/` at project format 12.
- `tests/journey_*.rs`: the choker, the circular display, a dome slice and
  Sean's eaves, each step a statement driven through the editor's
  inspector as a person does it. `lpc-mapping` has the same journeys as
  model edits.
- `tests/journeys.rs`: the hand-patching journeys, by keys alone, until the
  patch matches the piece (the lights as they are really wired).
