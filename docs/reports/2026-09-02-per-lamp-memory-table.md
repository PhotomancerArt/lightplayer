# Per-lamp memory table — what each lamp costs the engine, measured

Date: 2026-09-02. Tree: `7c80a273f` (main after #502) for the "before" figures.
Plan: `lp2025/2026-09-02-2154-per-lamp-memory-table`.

Every heap buffer whose size scales with lamp count, attributed to the struct
that owns it, in bytes per lamp, host and device, for three fixtures. The
question behind it: zook-dome (1,500 lamps) showed a first-frame `frame`
window of 136,652 B transient / 82,864 B retained on the RV32 emulator — six
times its shader compile — and the classic ESP32 (`fw-esp32v3`, a
110 KiB + 72 KiB = **186,368 B** arena, ~126 KB free after load) is the board
that project targets.

## Instruments

- **Host:** `lp-core/lpc-engine/tests/per_lamp_memory_table.rs` — a tracking
  `#[global_allocator]` brackets load, graphics + output provider install,
  tick 1 (no compile), tick 2 (compile), ticks 3–6, drop. Each fixture runs
  at two lamp counts and the **slope** is the per-lamp figure: a measurement,
  not a sum of code reading. An in-memory output provider is installed so the
  flush leg is measured (the sibling probe `zook_load_tick_memory.rs` never
  opens a port).

  ```bash
  cargo test -p lpc-engine --test per_lamp_memory_table -- --nocapture
  ```

  ⚠️ The host graphics backend is wasmtime (`lp-gfx-lpvm/src/target_backend.rs`,
  every non-device arch). Its sample-point and sample-out buffers live in
  wasm linear memory, pre-grown at engine init, so the host tracker **does
  not see** those two 8 B/lamp buffers. The device column does.
- **Device width:** the RV32 emulator, `lp-cli profile --collect alloc`
  (`--mode startup` and `--mode steady-render`), per-window budget figures
  and per-callsite live/peak tables. Emulator ≠ classic: the guest heap is
  320 K, `usize` is 4 B on both, the allocator differs, and the emulator's
  output provider has no `DisplayPipeline`.

**Check against the slopes.** Host tick 1 = 4 + 8 + 6 + 6 + 6 + 3 + 6 = **39**
(direct_channels, sampled_scratch, control_samples, buffer bytes, flush
samples, 8-bit frame, provider data) — measured 38.8 / 39.4. Load = 8 —
measured 8.0 / 8.9 (spans and the compact carrier's small per-strand rows).
Load transient = 32 — measured 32.2 / 32.3. Every host figure is accounted
for; there is no unexplained per-lamp owner.

**Device tick 1** adds the two JIT buffers: 39 − 6 (no host `PortState.data`)
+ 16 = **49 B/lamp** → 73,500 B of zook's 82,864 B `frame` retained; the rest
is per-port and per-open fixed cost. **Classic** adds the display pipeline:
55 B/lamp (interpolation off) to 70 (on + dither), plus 8 at load = 63–78
B/lamp all-in, consistent with the "≈59 B/LED post-M6" silicon figure in
`docs/debt/per-lamp-data-stored-three-times.md` (measured before
`sampled_scratch` existed).

| Owner | B/lamp | Scope | Seen as |
|---|---:|---|---|
| provider `raw: Vec<u8>` per `write` (host `MemoryOutputProvider`, `fw-emu` `SyscallOutputProvider`) | 3 per port, freed per port | host + emulator, not the ESP32 provider (it keeps `PortState.frame`) | host steady tick T = 3 × largest port (989 / 3,000); emulator steady frame 2,720 (P4) |
| `ProductScratch.rendered[].samples` — a patched fixture's whole product rendered, then copied out per run | 6 per lamp of every patched product | small-dome only here (both fixtures patched) | host steady tick T 42,278; emulator frame largest alloc 35,700 = 6 × 5,950. Not in this plan (future work) |
| per-port fragment/wire bookkeeping | ~400 B per port | dome-scale: 23 ports | host steady T 12,956 − 3,000 |

### Not lamp-scaled, but in the profile

- **`Vec<HwResource>` 36,864 B, one allocation, `grow_one`**: the emulator's
  permissive manifest (`lpc-hardware/src/manifest/default_manifests.rs`
  `permissive_emu_hardware_manifest`, 256 × 144 B). Not on the device (the
  classic manifest has 34 resources).
- **Output-open churn in the first frame** — `finish_grow` 4,445 allocs /
  471,644 B, `VirtualWs281xDriver::endpoints` 2,560 allocs / 31,385 B,
  `format_inner` 1,300 / 34,592 B, `String::clone` 1,786: every port open
  re-enumerates all 256 manifest resources (`endpoints()` →
  `endpoint_status` per resource, `Vec<HwEndpoint>` grown by push). This is
  what makes the emulator's first-frame *transient* (136,652 B) overstate the
  device; the *retained* figure transfers. Owner: the
  `HwRegistry::endpoint_status_for` work in `lpc-hardware`.
- Gamma and sRGB tables are `const` (no heap). The map2d document is dropped
  after the mapping is built (`FixtureMap2dSource` keeps location + revision).

## After (2026-09-02, branch of PR #503 merged with main at 34ff04f8d)

What changed: `FixtureNode::sampled_scratch` gone (the sample-out is
borrowed in place, `LpGraphics::sample_out_data`); `OutputNode::control_samples`
and `EngineServices::flush_samples` gone (the runtime buffer stores `u16`
samples, the node takes that storage for the frame, the flush borrows it);
the map2d resolver streams into the carrier's own buffer and is fitted in
place; the loader and the fixture's asset refresh no longer resolve the
document a second time for object spans; the emulator and host output
providers keep a per-port 8-bit frame buffer.
