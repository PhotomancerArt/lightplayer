# The PAC calls `SPI*.ctrl2` write-only, and the mask ROM reads it back twice

**Symptom** — the first run of `tests/flash_over_socket.rs` with `SPI1` named
in its `strict_grade_blocks` scope at `documented` refused itself, 3.86 M
cycles in, with no useful message on the flasher's side:

```text
the flasher said Some("Error while connecting to device");
the machine's first strict violation was Some(StrictViolation {
  cycle: 3857231, pc: 1073891756, address: 1610625040,
  width: Word, access: Read, in_mmio_window: true, grade: Some(Modeled) })
```

`address` is `0x6000_3010` — `SPI1.ctrl2` — and `pc` is `0x4002_49ac`, inside
the vendored mask ROM.

**Cause** — `RegFile::with_pac_grades()` grades a register `documented` only
when the generated access table calls it `ReadWrite`, and `modeled`
otherwise. `lp-emu/esp/lp-emu-esp32c6/src/regs/spi1.rs` carries

```rust
(0x010, Access::WriteOnly),
```

so `ctrl2` came out `modeled`, and a run that asked for `documented` refused
the ROM's own flash-timing setup.

`ctrl2` is not write-only. `spi_common_set_flash_cs_timing` at `0x4002_497e`
read-modify-writes it **twice**, for SPI0 at `0x6000_2000` and then for SPI1
at `0x6000_3000` (`riscv64-unknown-elf-objdump -d
lp-emu/esp/roms/esp32c6_rev0_rom.elf`):

```text
400249a0:  600037b7   lui  a5,0x60003
400249a4:  4f98       lw   a4,24(a5)      # user  +0x18
400249a6:  0c076713   ori  a4,a4,192
400249aa:  cf98       sw   a4,24(a5)
400249ac:  4b98       lw   a4,16(a5)      # ctrl2 +0x10   <-- the refused read
400249ae:  c1f77713   andi a4,a4,-993     #   keep everything but [9:5]
400249b2:  04076713   ori  a4,a4,64       #   cs_hold_time = 1
400249b6:  cb98       sw   a4,16(a5)
400249b8:  4b98       lw   a4,16(a5)      # ctrl2 again
400249ba:  9b01       andi a4,a4,-32      #   keep everything but [4:0]
400249bc:  00176713   ori  a4,a4,1        #   cs_setup_time = 1
400249c0:  cb98       sw   a4,16(a5)
400249c2:  8082       ret
```

Both `andi`s preserve bits the ROM did not write, so the ROM does not merely
touch the register — it **depends on the value it reads back**. A register the
mask ROM reads is readable, whatever the PAC's access attribute says.

Nothing about the emulator's *behaviour* was wrong. `RegFile` does not enforce
the access table — the only consumer of `Access` is `with_pac_grades()` — so
the read returned the stored word and the ROM's read-modify-write did exactly
what it does on silicon. What was wrong was the **grade**, which is the claim
the model makes about itself, and it was wrong in the direction that hides a
working path behind a refusal.

**Fix** — `periph/spi1.rs` states the grade by hand, with the disassembly
above as its source:

```rust
.with_grade(CTRL2, RegGrade::Documented)
```

`src/regs/**` is generated by `scripts/emu/pac-regnames.py` and is never
hand-edited, so the correction belongs in the block, next to the other two
hand-written rows (`cmd`, `rd_status`). `Spi1::reg_grade`'s doc comment
carries the same evidence in its table.

**The open part** — two of them.

1. **SPI0 is the same register in the same ROM function**, four instructions
   earlier, and `periph/spi0.rs` publishes no grade table at all today, so
   nothing refuses. The moment somebody adds `with_pac_grades()` there it will
   refuse in exactly this place. It is not fixed here because M3 P2 owns
   `spi1.rs` and does not own `spi0.rs`, and SPI0 is not in any strict-grade
   scope this milestone claims.

2. **`ctrl2` is unlikely to be the only one.** The rule "PAC `ReadWrite` ⇒
   `documented`" treats a wrong access attribute as a statement about
   modelling quality, and the two are unrelated. Every `WriteOnly` and
   `ReadOnly` row in the generated tables is a `modeled` grade nobody chose,
   and this one was found only because a new path read one. A sweep that
   cross-references the access tables against the reads the vendored ROM
   actually performs would turn "the attributes the PAC states" into "the
   attributes the part honours"; it was out of M3 P2's scope.
