# ESP32-C6 RMT WS281x output is dark on current firmware

**Found**: 2026-08-31, device-model round-2 G1 bench (the first time a
C6 with LEDs attached met current firmware).
**Status**: OPEN — root cause unknown.

## Symptom

A Seeed XIAO ESP32-C6 with three known-good WS281x strips (data on
D8/D9/D10 = GPIO 19/20/18) shows NO light under current firmware, in
two independent configurations:

1. **Full app firmware** (`fw-esp32c6`, commit b16f944a1d50 ≈ current
   main; round 2 contains no output-path changes): boot log is
   completely healthy — `Hardware manifest: seeed/xiao-esp32-c6`,
   `Esp32C6RmtWs281xDriver: 2 WS281x channels for 2 declared
   (ch0_blocks=1 ch0_window_words=48 ch0_half_words=24)`,
   `::open endpoint=ws281x:local:D10 gpio=/gpio/18 ws281x_ch=0
   rmt_slot=0 bytes=180`, engine at 43 fps, zero warnings. Dark.
2. **`test_rmt` harness** (feature `esp32c6,test_rmt` — raw patterns,
   no pipeline, drives gpio18 directly). Dark.

**Known-good reference**: the SAME board + SAME strips animated
earlier the same day under its months-old previous firmware
(wire proto 12 — date it via the `WIRE_PROTO_VERSION` bump history in
`lp-core/lpc-wire/src/server/hello.rs`).

## Why this went unseen

Every recent C6 bench walk (round-1 G1 included) used boards with no
LEDs attached; the classic V3/dome path (separate driver) kept
working. The regression window is proto-12 era → now.

## Suspects (code-read before bisecting; each touched this ground)

- The RMT block-plan rework (`fw-esp32c6/Cargo.toml` notes "the former
  `ws281x_2blocks` feature is gone: the RMT block plan is now …").
- esp-hal upgrades across the window (RMT + clock APIs; the boot line
  says "Initializing RMT peripheral at 80MHz…" — a clock/divider
  change would silently wreck bit timing while logging success).
- Packed display layouts (proto 18) — full-fw path only; the harness
  being dark too argues BELOW the pipeline.
- io_task/serial rework (#448) — unlikely (harness has no serial load).

## Verification tools

`ws281x_telemetry` feature (counters), `test_rmt` harness,
`fixture-fw`-style build+flash (BUILD FROM THE CRATE DIR — a
workspace-root cargo build misses the linker script), espflash CLI,
human eyes on the bench (no logic analyzer on hand).
