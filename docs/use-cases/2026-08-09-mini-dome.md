# The small-dome — N-way symmetric repeat, re-patched every install

*(Historical name: "the mini-dome" — this file keeps its dated path
for link stability. The real installs are registered in
[the three domes](2026-08-28-three-domes.md).)*

The dome archetype: a structure built from **identical repeated
units** (panels, sectors, struts) whose **mapping never changes**
but whose **plugging changes every single build**. The physical
crew connects units to whatever jack is nearest and the software
is expected to sort it out afterwards.

The concrete cases (details: [the three domes](2026-08-28-three-domes.md)):

- The zook dome: ~1500 LEDs, one strut path repeated with 5-way
  symmetry, five controller ports of 300 LEDs each. The as-built
  plugging is a permutation — sector *k* landed on port
  `(1,5,4,3,2)[k]` — which today lives hand-coded in the example's
  channel order: a patch file trying to be born.
- The big dome — radiance (lp2014 era, "dome scale"): 190 panels of
  119 LEDs across ten controllers, plus always-lit door fixtures
  sharing outputs. Roughly **90% of all clicks** in the old software
  were dome patching, because "plug into random jacks, fix it in
  software" beats careful cabling on a build site.

## Demands on the system

Status marks as of slice 2 (2026-08-10):

- ✅ **Instance-grain patching.** The patchable unit is the repeat
  instance (a panel, a sector) — a UI grain over object-relative
  storage; storage is `(object path, optional range)` — a path into
  the mapping's object tree (`/sector/2`), so instance boundaries
  re-derive from the mapping and entries survive the structure
  growing (patch format 2, D46).
- ✅ **Stable object identity** in the mapping doc, so patch entries
  survive edits to *other* objects (map2d format 3).
- ✅ **Per-entry direction and rotation.** A panel plugged backwards
  needs `reversed`; a symmetric panel seated in the wrong
  orientation needs an offset stepped by a meaningful stride (the
  panel's edge length) — "rotation is fake but very useful." The
  stride is intrinsic where the shape has one (a closed polygon's
  lamps per side, when the count divides) and an authored override
  where it doesn't (the example's 119-lamp panels carry
  `"stride": 40`, the open chevron door `"stride": 180`).
- ✅ **Multi-port, multi-output scatter.** Instances land on arbitrary
  ports of arbitrary outputs; the patch view must show every port
  as a row and every instance's destination.
- ✅ **Bulk operations.** Swap two ports, shift a port's contents,
  clear the patch for a *selection* of fixtures (the dome
  re-patches every install; the orb next to it is wired forever) —
  the patch surface's verbs (slice 2 P6).
- ⏸ **Live hardware feedback.** Select an instance, see it pulse on
  the physical build (the lp2014 `debugChannels` workflow —
  patching is done standing next to the dome). CHIPPED in slice 2
  (Q27): the surface highlights client-side; the sim/hardware pulse
  is a follow-up.

## Example project

**Shipped** with slice 2 as a 177-lamp miniature; rebuilt
2026-08-28 at **full scale** as `examples/small-dome` — the real
Small Dome, deliberately **many-to-many** (Yona steer, 2026-08-09:
the peach is many-to-one, real zook is one-to-many; nobody covered
fixtures *sharing* outputs). TWO fixtures × TWO named outputs:

- `dome`: ten panel-position objects (`rim-a/b`, `band-a..d`,
  `cap-a..c`, `zenith`), each a 5-way repeat of a 119-lamp polygon
  — 50 suspended triangle panels, the patch grain the crew actually
  plugs (`/band-a/3`). Authored `"stride": 40` (~one panel side;
  119 doesn't divide by 3). The patch carries the as-built install
  across the two boxes' 13-port tables — one panel reversed, one
  rotated a side.
- `doors`: ONE chevron door `{id: "door"}` (360 lamps, 180 up each
  ~10' leg, authored `"stride": 180`), sharing the TAIL of a box-1
  port with a panel, rotated by one leg.

At 6,310 lamps the example doubles as the desktop-scale sim stress
fixture. The map2d geometry is a plan view of the real structure —
the 40 2V faces plus the riser rung's 10 downward triangles, the
door's feet on the riser's ground circle — and ALL six wiring
artifacts (two map2d, two patch, two output nodes) are generated
deterministically by `tools/lpt-geodome` (`cargo run -p
lpt-geodome`), which is also where a future parametric dome shape
in the mapper would start.

Engine truth pinned by `lpc-engine` tests
(`small_dome_scatter.rs`, the A1 golden oracle); the guided tour is
`docs/user-guide/patching-the-dome.md`.
